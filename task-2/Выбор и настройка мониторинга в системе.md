## Выбор и настройка мониторинга в системе

#### Мотивация
Внедрение системы мониторинга позволит компании отслеживать текущее состояние всех систем и так же быстро
реагировать на отказ той или иной части системы. Так же можно будет своевременно реагировать на отказы партнерских систем
и уменьшить количество жалоб от клиентов и анализировать узкие места системы.

#### Выбор подхода к мониторингу

- RabbitMq - используем метод USE, так как он хорошо работает с ресурсами производительность которых снижается
при интенсивном использовании

- Для внешнего API - можно использовать RED. Он хорошо подходит для сервисов которые управляются запросами.

- Для все остальной системы используем "Четыре золотых сигнала". С помощью этого подхода мы сможем заранее замеитить
аномалии в системе и быстро среагировать на ситуацию

#### Список отслеживаемых метрик

RabbitMq:
- Number of dead-letter-exchange letters in RabbitMQ - количество ошибочных сообщений
- Number of message in flight in RabbitMQ - количество сообщений в обработке консьюмером


Бизнес сервисы:
- RPS - показывает нагрузку на сервис
- ERROR Rate - кол-во ошибок по сервисам, поможет выявлять проблемы
- Ram/Cpu Utilisation - контроль ресурсов для масштабирования

БД:
- Number of connections - количество коннектов к БД
- Size - размер БД, мониторим чтобы избежать переполнения
- Ram/Cpu Utilisation - контроль ресурсов для масштабирования

#### План действий
- Развернуть Prometheus и Grafana
- Развернуть инстансы node_exporter для экспорта метрик
- Добавить в бизнес сервисы библиотеки для экспорта метрик
- Создать дашборды в графане для мониторинга
- Настроить алерты
- Настроить уведомления на почту/мессенджеры для быстрого реагирования
