# Планирование: анализ, идентификация проблем и поиск решений

### Потенциальные проблемные места:

- MES получает данные о заказах из интернет магазина в файловом хранилище а не по API или messaging, что является плохой практикой и может привести к несогласованности данных
- CRM Api получает данные о заказах в БД shop DB, нужно так же выстраивать взаимодействие через API или messaging
- Через API заказ на новое изеделие попадает из MES в брокер сообщений, а оттуда его забирает CRM. Жалобы на задержку заказов увеличились
- Добавились жалобы со стороны API. Представители компании ежедневно сообщают, что не получили свои заказы
- Жалобы от операторов, что первая страница MES системы долго загружается.
- Нет горизонтального масштабирования сервисов, нет отказоустойчивости
- Нет репликации БД, есть риск потери данных

## Инициативы

- Доработка CRM системы, своя бд и возаимодействие c Shop API через брокер
- Расчет стоимости заказов сделать асинхронным (RabbitMq) и вынести в отдельный сервис
- Взаимодействие через RabbitMq Mes Api с CRM, для ускорения старта производств
- Настроить репликацию и кеширование заказов Mes Api
- Внедрить мониторинг и алертинг (Grafana/Prometheus)
- Настроить горизонтальное масштабирование для сервисов
- Настроить трейсинг
- Добавить централизованное логирование

## Приоритизация инициатив
1. Расчет стоимости заказов сделать асинхронным (RabbitMq) и вынести в отдельный сервис    
   Важно для усорения скорости обработки заказов
2. Взаимодействие через RabbitMq Mes Api с CRM, для ускорения старта производств   
   Важно для усорения скорости обработки заказов и исключения потерянных заказов
3. Доработка CRM системы, своя бд и возаимодействие c Shop API через брокер
   Исключение потерянных заказов
4. Настроить репликацию и кеширование заказов Mes Api, для ускорения вывода дашбордов
   Ускорение вывода дашборда для операторов
5. Внедрить мониторинг и алертинг (Grafana/Prometheus)
   Необходимо для своевременного реагирования на инцинденты
6. Настроить горизонтальное масштабирование для сервисов
   Обеспечит отказоустойчивость системы
7. Настроить трейсинг
   для выявления проблеммных и медленных запросов
8. Добавить централизованное логирование   
   для упрощения разбора проблема внутри сервисов и снижения нагрузки на поддержку
