# Архитектурное решение по логированию

#### Список систем для сбора логов
Основной упор надо сделать на бизнес сервисы:

1. ShopApi  
INFO - авторизация, создание заказа  
WARN - неудачные авторизации  
ERROR - все виды ошибок  
DEBUG, TRACE - можно использовать для dev стенда
2. CrmApi   
INFO - изменение статуса заказа, новый заказ из API
WARN - неудачные авторизации
ERROR - все виды ошибок
DEBUG, TRACE - можно использовать для dev стенда
3. MesApi
INFO - время расчета для модели
WARN - можно дополнительно писать для слишком долгих расчетов
ERROR - все виды ошибок
DEBUG, TRACE - можно использовать для dev стенда

Так же можно собирать логи с БД и брокера сообщений и продумать сбор логов с фронтендов.

#### Мотивация
Плюсы внедрения логирования:

- Добавление логирования упростит разбор инцидентов. 
- Позволит быстро реагировать на жалобы клиентов, позволит подтвержать/отклонять их.
- Логи являются источником информации для мониторинга.

Приоритеты:

1. Shop Api - для устранения потерь заказов
2. Mes Api - для устранения потерь заказов
3. CRM Api - для устранения потерь заказов
4. RabbitMq - для устранения потерь заказов
5. Фронтенды - ошибки клиентов
5. PostgreSQL - анализ работы бд

#### Предлагаемое решение
Стек:
- ElasticSearch - для аггрегации логов
- Fluent Bit - сбор логов и отправка в ElasticSearch
- Kibana - фронт для ElasticSearch
- Java сервисы библиотека Slf4j, C# - Serilog, Фронт - log4js

Безопасность:

Чувствительные данные которые должны бить либо исключены либо замаскированны:    
- Данные банковских карт, реквизиты счетов
- Персональные данные клиентов
- Данные авторизации

Права доступа к логам:
- DevOps - на тестовых средах
- Бэкенд-разработчики, Фронтенд-разработчики, QA-инженер - на тестовых средах
- Продакт-менеджер - нет
- Тимлид - да для мониторинга состояния системы
- Операторы / Продавцы - нет

Политика хранения логов:
- Отдельный индекс на сервис: shop-api-*, crm-api-*, mes-api-*, rabbitmq-*.
- Шаблоны индексирования: маппинги под поля trace_id, order_id, latency_ms, event_name.

Срок хранения:

- Логи приложений (онлайн-магазин, CRM, MES): 30 дней. Этого достаточно для расследования инцидентов последнего месяца. Старые логи архивировать в холодное хранилище с шифрованием.
- Логи RabbitMQ (интеграция): 7 дней.
- Логи аудита безопасности (кто заходил в логи, изменения прав доступа): 1 год (в соответствии с требованиями к аудиту информационной безопасности).

Мероприятия для  превращения системы логов в систему анализа логов:

Алерты:
- 5xx errors - количество 500 ошибок за 5 минут
- Slow query в БД - кол-во медленных запросов за 5 минут
- RabbitMQ - количество мусорных сообщений за 5 минут
- Ошибка расчета Mes -кол-во ошибок за 5 минут
- Нет логов от сервиса - индикатор проблем

Аномалии по логам:
- DDoS/Боты - всплеск созданых заказов за минуту
- Долгий статус заказа - изменение статуса заказа дольше обычного срока
- Нет логов от сервиса
- Повторяющиеся ошибки
- Большое количество неудачные логинов от пользователя
- Массовое чтение - один пользователь слишком часто перезапрашивает страницу
